verified duʿāʾ inventory. No UI components exist yet, per the brief's checkpoint.

| Decision | Choice |
|---|---|

## 1. How the Arabic works now

**No Arabic is authored anywhere in this repository.** `content/duas.ts` names
āyāt and, where a supplication sits inside a longer verse, a half-open word
range. `npm run content:fetch` resolves those against the `quran-uthmani`
edition and writes `content/generated/arabic.json` plus a SHA-256 per entry in
`content.lock.json`.

This is stricter than fetching once and committing, and the Phase 1 audit is
why. Both scripture errors it found — `sulaiman-27-19` carrying the text of
46:15, and `ayyub-38-41` with words inserted at an excerpt boundary — read
fluently, cited plausibly, and had translations that agreed with the corrupted
text. Review does not catch that. A hash does.

Verified working:

```
$ npx tsx scripts/verify-content.ts        # clean
✓ all 52 entries match content.lock.json   exit 0

$ # after flipping one character of one hash
✗ 1 problem(s):
  MISMATCH yunus-la-ilaha-illa-anta (21:87)
           locked  b3c8f086c2f18876…
           derived 83c8f086c2f18876…
                                           exit 1
```

Both Phase 1 errors are now correct at the source:

| Entry | Was | Now |
|---|---|---|
| Sulaymān 27:19 | ended `وَأَصْلِحْ لِي فِي ذُرِّيَّتِي…` (46:15) | ends `وَأَدْخِلْنِى بِرَحْمَتِكَ فِى عِبَادِكَ ٱلصَّٰلِحِينَ` |
| Ayyūb 38:41 | `رَبِّ إِنِّي مَسَّنِيَ…` (words inserted) | `أَنِّى مَسَّنِىَ ٱلشَّيْطَٰنُ بِنُصْبٍۢ وَعَذَابٍ` |

### Excerpts are now data

44 of 52 entries are excerpts. Each records `fromWord`, `toWord`, and a note
saying what was cut, and the UI will disclose it. Every boundary was chosen by
reading `scripts/inspect-ayah.ts` output against a Pickthall gloss — never by
typing or recalling Arabic. The old corpus had 16 silent excerpts and no field
in which to record that fact.

Two apparatus characters are stripped before indexing, and only when they stand
alone as their own token: `۞` (rub-el-ḥizb) and the waqf marks `ۖ ۗ ۘ ۙ ۚ ۛ ۜ`.
They are scribal marks for reciters, not part of the āyah, and leaving them in
would shift excerpt indices depending on where a pause happens to fall.
Combining marks attached to letters are never touched.

## 2. Turkish

**Every entry carries exactly one Turkish translation**, and the page says
where it came from.

| Entries | Turkish | Why |
|---|---|---|
| 57 Qurʾānic | **Elmalılı Hamdi Yazır** (d. 1942, public domain) | Published, attributed work, fetched per-āyah so it always covers the same extent as the Arabic beside it. |
| 5 ḥadīth | **Umut Candan** | No public-domain ḥadīth translation exists to fetch. |
| 1 attributed | Project draft, labelled | No Turkish edition of the passage to fetch. |

**Why one and not two.** An earlier pass showed Elmalılı and the project's own
Turkish side by side. That was a mistake: two renderings of the same scripture
invite the reader to adjudicate between them, which is not a question a reader
should be handed, and it lengthened the page for no gain.
`scripts/check-coverage.ts` now fails the build on more than one translation per
language per entry.

**Nothing was lost by choosing.** All 47 legacy Turkish translations remain in
`data/prayers.json` and `content/generated/legacy-migration.json`, and
`scripts/migrate-legacy.ts` still fails the build if any goes missing from the
repository. The ḥadīth entries display them.

Fetching per-āyah also fixed a real defect. The project's own Turkish was
written one āyah at a time against the old corpus, so on entries that now span a
range — 20:25–28, 14:36–41, 2:127–129, 26:83–89 — it covered only the first
āyah. A reader saw four āyāt of Arabic and one sentence of Turkish.

## 3. Theme taxonomy

16 themes, in `content/themes.ts`. Every one is phrased as a situation in the
second person rather than as an abstract noun — "When there seems no way out",
not "Hardship". Someone arriving mid-crisis is looking for their own situation
in a list, not looking up a subject index. The abstract term is demoted to the
description, where it still supports search.

No second level. A taxonomy that needs drilling has stopped being a door; where
an entry belongs in several places it carries several themes.

## 5a. Material outside the Qurʾān and Sunnah

One entry — Dāwūd, Psalm 51:1–2 — comes from a scripture outside the Islamic
tradition. It exists because the Qurʾān records that he sought forgiveness
(38:24) without quoting his words, and an empty page said something false about
the record.

It is held in `content/attributed.ts`, has its own `source.type`, renders with a
distinct treatment and a prominent notice, and is never mixed into the Qurʾānic
entries. It carries no chain of transmission and no scriptural authority in
Islam, and the page says so. The text is fetched from the World English Bible
(public domain) and hash-locked, because the rule that scripture is never
written from memory applies to it too.

Selection is narrow by design: a supplication in form, traditionally attributed
to that prophet, containing nothing that contradicts Islamic belief about God.

## 5. Open items

**Dāwūd now has two entries.** The first is Qurʾānic and was simply missed
earlier: **27:15** quotes his and Sulaymān's own words — *al-ḥamdu lillāhi
alladhī faḍḍalanā* — which is a ḥamd rather than a petition, and is labelled as
such. The second is Psalm 51:1–2, attributed to him outside the Islamic
tradition and shown in its own clearly-labelled treatment (see §5a).

**The 5 ḥadīth duʿāʾ now ship**, at `needs-review`, each with a visible notice
that its reference number and grading await verification against a printed
edition and that its Arabic is hand-entered rather than fetched. The schema
requires `grading` and `gradedBy`, which they carry.

**2:286 and its neighbours are placed.** A third grouping — *Duʿāʾ the Qurʾān
teaches* — holds 2:286, 3:8, 3:147 and 25:74: supplications the Qurʾān gives to
be said without quoting a named speaker.

**Transliteration is generated** deterministically from the hash-locked Arabic
by `scripts/transliterate.ts`, in a simplified ALA-LC scheme. It cannot drift
from the Arabic because it is a pure function of it. It has not had a human pass.

**Context citations — done.** Every Qurʾānic entry now carries **Tafsīr
al-Jalālayn**, quoted and attributed, fetched by `scripts/fetch-tafsir.ts`.
Nothing is marked "awaiting a citation" any more, because a note saying a
citation is missing is not a citation.

**Asbāb al-Nuzūl was dropped, deliberately.** Al-Wāḥidī's occasions of
revelation are the better source for this field and the aggregator exposes a
slug for them — but that slug returns text byte-identical to
`en-al-qushairi-tafsir` and near-identical to `en-kashf-al-asrar-tafsir`, in a
Sufi register nothing like al-Wāḥidī. At least two of those three labels are
wrong and there is no way to tell which from here. Shipping it would have
attributed one scholar's words to another on thirteen pages — the same class of
error as a mis-cited āyah, and just as invisible, since the prose reads well.
`assertDistinct` in the fetcher now fails the build if two sources ever return
the same text again.

## 6. What runs

```
npm run content:fetch      # resolve Arabic + translations, write lock file
npm run content:verify     # CI guard — fails on any drift
npm run content:inventory  # regenerate the table above
npm run typecheck          # tsc --noEmit, strict
npx tsx scripts/inspect-ayah.ts --compact 21:87   # choose excerpt boundaries
npx tsx scripts/migrate-legacy.ts                 # carry Turkish forward
```

`scripts/.cache/` holds fetched āyāt so repeated runs and CI do not hammer a
free public API. It is gitignored; `content.lock.json` is the source of truth.
